# Cápsula: Biblioteca REA

Abierta: 2026-10-19 · id: 979b688a-825f-4ac4-81dd-ef1e46ccd1cb

## Objetivo

Construir Biblioteca REA: una aplicación visual para organizar las investigaciones del usuario,
piezas reutilizables y soluciones, con una ficha permanente por elemento, filtros por sector y
capacidad, y un recorrido real de "Analizar" que invoca REA, muestra progreso real y guarda el
resultado en la ficha, sin perderlo al recargar ni duplicarlo.

## Alcance

- Verificado al empezar: ninguna Biblioteca REA existía en código, solo documentos de propuesta
  (`documentos/2026-10-18-mapa-de-investigacion-y-modulos-reutilizables.md` y el plan del
  2026-10-17). REA no estaba instalado ni registrado como MCP en este Mac (sí lo estuvo en un
  contenedor de nube distinto, en la cápsula "Prueba" — decisión no aplicable a esta máquina).
- Decidido por el agente y comunicado antes de ejecutar (no requería elegir entre opciones del
  usuario): repositorio propio y privado `mgmejiaar-lab/biblioteca-rea`, separado del fork
  público de REA, porque la biblioteca referencia investigaciones privadas (Bancavalor,
  Jurídico, Wispr) y el fork de REA prohíbe copiar información privada. REA se consume como
  motor externo (`spawn` del binario global); no se tocó su código.
- Autorizado explícitamente por el usuario (pregunta de opciones, 2026-10-18): el esquema
  `biblioteca_rea` vive en el proyecto Supabase ya existente "Conectia Apps"
  (`sippfegejzylnnotqwea`), no en un proyecto nuevo.
- Autorizado explícitamente por el usuario (resumen "Dónde va a quedar" + confirmación,
  2026-10-18): aplicar el esquema, el rol `biblioteca_rea_app` con RLS, y los datos iniciales en
  ese proyecto compartido, y continuar con la prueba real de análisis.
- Avisado como acceso fuera de este proyecto (sin objeción del usuario, igual que en la cápsula
  "Prueba"): instalación global de `rea-agents` en `~/.npm-global` y registro MCP para Claude
  Code en `~/.claude.json` de este Mac, con `rea setup --client claude_code --yes` (plan
  mostrado primero con `--dry-run`, respaldo automático creado).
- No se tocó Bancavalor ni se activó DIAN. No se usó la clave `service_role` de Supabase dentro
  de la app (solo el rol dedicado `biblioteca_rea_app`); el esquema se aplicó con
  `supabase db query --linked`, sin necesitar ni guardar la contraseña de administrador del
  proyecto.
- Primera entrega acotada al recorrido pedido: ficha permanente, filtros por sector/capacidad,
  "Analizar" con el comando real `rea analyze <ruta>` sobre rutas locales permitidas, progreso
  en vivo, resultado persistido, "Investigar más" sin perder el historial. Sin mapa de
  relaciones visual, comparación lado a lado, "Aplicar mejora" al código, ni conexión con
  Conectia360 — quedan fuera de esta entrega, documentado así en
  `biblioteca-rea/docs/DECISIONES.md`.

## Avances comprobados

- Repositorio `mgmejiaar-lab/biblioteca-rea` creado (privado) y con el primer commit subido a
  `main`. Next.js 15.5.28 (parchado; la versión inicial 15.1.6 tenía una CVE conocida, se
  corrigió antes de seguir) + TypeScript + Tailwind + `pg`. `npx tsc --noEmit` y `npm run build`
  pasan (el build sin `DATABASE_URL` falla solo al recolectar datos de página estática, esperado
  sin credenciales en ese paso; con `.env` real sí construye — ver más abajo).
- REA instalado en este Mac: `/Users/manuel/.npm-global/bin/rea`, versión 6.7.0. Registrado como
  MCP de Claude Code (`rea setup --client claude_code --yes`, con `--dry-run` mostrado antes);
  pendiente confirmar que `mcp__rea__*` carga en la próxima sesión nueva (requiere reiniciar
  Claude Code).
- Esquema `biblioteca_rea` aplicado en Supabase "Conectia Apps" vía `supabase link` +
  `supabase db query --linked`: 10 tablas, RLS habilitada y restringida al rol
  `biblioteca_rea_app` (sin `bypassrls`, sin acceso de `anon`/`authenticated`/`public`). Datos
  iniciales cargados y verificados por consulta directa: 3 sectores, 4 capacidades, 4 fichas
  reales (Dictado para chats —pieza probada—, la investigación de gestión documental, el lector
  de facturas marcado explícitamente como "especificación, sin implementación propia", y la
  investigación de Orbital).
- **Recorrido completo probado de punta a punta** con el navegador del Taller contra un servidor
  de desarrollo temporal (puerto 4123, detenido al terminar): login con secreto compartido →
  catálogo con filtros → ficha "Dictado para chats" → escribir pregunta real + ruta local
  (`dictado-para-chats/src`, repositorio propio del usuario, sin datos de cliente) → "Analizar"
  → encargo "En cola" → progreso real en vivo por sondeo (p. ej. "Parsing and projecting
  index.d.ts (2/5)", tomado literalmente de la salida de REA) → "Listo" en ~3.6s con evidencia
  real de REA (grafo de módulos, imports/exports, confianza y limitaciones declaradas, sin
  inventar nada) → recarga de página: el mismo encargo persiste, sin duplicarse → "Investigar
  más" con una segunda pregunta: crea un segundo encargo, conserva el primero visible con su
  evidencia.
- Comprobado por API directa (`curl`, dos POST concurrentes idénticos): el límite de encargo
  activo duplicado funciona — ambas respuestas devuelven el mismo `id` de encargo, no se crean
  dos filas. Comprobado también que una ruta fuera de `ALLOWED_ANALYSIS_ROOTS` (`/etc/passwd`) se
  rechaza con error claro, no se ejecuta.
- El secreto de acceso (`APP_SHARED_SECRET`) apareció una vez en la salida de un comando de
  depuración durante la prueba; se rotó inmediatamente después (valor nuevo generado y guardado
  solo en `.env` local, nunca mostrado en el chat).
- Documentación propia del repositorio nuevo: `README.md`, `AGENTS.md`, `CLAUDE.md`,
  `docs/DECISIONES.md` (con el razonamiento de cada decisión técnica de esta tarea).

## Pendientes

- Confirmar que `mcp__rea__*` carga en la próxima sesión nueva de Claude Code en este Mac
  (pendiente general del proyecto REA, no solo de esta tarea).
- La app quedó probada en un servidor de desarrollo temporal, ya detenido. Para volver a verla,

  crear proyectos nuevos desde este chat) y vincular sus llaves (`.env` ya tiene los valores

- `npm audit` señala 2 vulnerabilidades (moderada/alta) en la copia interna de `postcss` que trae
  Next.js 15.5.28; el arreglo disponible exige subir a Next 16 (cambio mayor). Riesgo práctico
  bajo mientras la app no procese CSS de terceros; queda anotado en
  `biblioteca-rea/README.md` como pendiente de prioridad baja, no bloqueante para esta entrega.
- El ejecutor solo admite el comando `analyze` sobre rutas locales (sin URL ni archivo subido
  todavía) — alcance explícito de esta primera entrega, documentado en
  `biblioteca-rea/docs/DECISIONES.md`.
- Sin motores nativos (Ghidra/IDA/Hopper/jadx) configurados: cualquier análisis que los necesite
  se reportará como limitado por REA mismo, no se ha probado ese caso.
- No se ha probado el recorrido en móvil ni con otro usuario; sigue siendo una herramienta de un
  solo usuario (secreto compartido, no Supabase Auth completo — razón documentada en
  `biblioteca-rea/docs/DECISIONES.md`).
- No se implementó mapa de relaciones visual, comparación lado a lado, "Aplicar mejora" al
  código ni conexión con Conectia360 — quedan fuera de esta primera entrega por alcance, no por
  olvido.
