## Avances comprobados

- Compilar desde fuente (`npm run build:cached`) falla por OOM: este contenedor tiene cgroup con límite de 2 GiB de RAM (`/sys/fs/cgroup/memory.max`), `tsc` muere (exit 137, oom_kill confirmado en `memory.events`) incluso limitando `--max-old-space-size=1536`. No se reintentó más tras el 2º fallo (regla de "como mucho un reintento"). NO es necesario para el objetivo: ver alternativa abajo.
- Alternativa que SÍ funciona sin compilar: paquete publicado en npm, instalado globalmente con prefijo propio del usuario (el prefix por defecto `/usr/local` no es escribible por el usuario `node`, uid 1000):
  `npm install --global --prefix /datos/home/.npm-global rea-agents@6.5.0`
  Binario resultante: `/datos/home/.npm-global/bin/rea`. Probado con `--help`, `doctor`, `capabilities`: funciona.
- Bug real encontrado y evitado: el comando que `rea setup` registra por defecto (`npx -y rea-agents@6.5.0 mcp`) falla de forma intermitente/reproducible (3/3 en prueba) con `sh: 1: rea: not found` cuando el proceso recibe datos por stdin de inmediato (igual que hace un cliente MCP real al conectar). Parece un problema de resolución de bin de `npx` con paquetes de dos bins (`rea` y `rea-agents`) al fijar versión exacta — no es un bug de REA. El binario global directo (`/datos/home/.npm-global/bin/rea mcp`) NO tiene este problema (3/3 pruebas con stdin ok, repetido).
- Se reconfiguró el registro MCP de Claude Code para usar el binario global directo en vez de `npx`:
  `/datos/home/.npm-global/bin/rea setup --client claude_code --yes` → `configured_claude_code`.
  Comando registrado ahora en `/datos/home/.claude.json`: `"/datos/home/.npm-global/bin/rea" "mcp"`. Respaldo automático de REA en el mismo directorio (`.claude.json.rea.backup*`).
  Skill "reverse-engineer-anything" instalado en `~/.claude/skills/` (207 herramientas, estado "aligned").
- Motores nativos (Ghidra/IDA/Hopper/jadx) NO están configurados en este entorno — análisis de binarios nativos/APK con decompilador no disponible todavía. Análisis estático (artefactos, PE/.NET managed, JavaScript/Electron) sí disponible sin motor adicional.

El detalle interactivo (reconectar un servidor puntual) solo está disponible "in the terminal" — el chat del Taller no es una terminal interactiva real, así que `/mcp` aquí no permite reconectar manualmente.
